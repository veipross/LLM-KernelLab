# LLM-KernelLab v0.2.0 Fused Residual RMSNorm 技术报告

## 1. 项目介绍

LLM-KernelLab 是一个面向大语言模型（Large Language Model,
LLM）推理优化的 GPU Kernel 实验项目。

项目基于 PyTorch 和 Triton，实现 Transformer
推理过程中的高频计算算子优化，并通过 Benchmark
分析不同实现方式的性能差异。

当前项目主要研究：

-   Triton GPU Kernel 开发
-   Transformer 算子优化
-   Operator Fusion（算子融合）
-   GPU Memory Access 优化
-   Kernel 性能分析

目前已经完成：

-   v0.1.0：RMSNorm Triton Kernel
-   v0.2.0：Fused Residual + RMSNorm Triton Kernel

## 2. 背景与优化动机

在 Transformer 模型中，Residual Connection（残差连接）和 RMSNorm
是非常常见的计算模块。

典型计算流程：

``` python
hidden_states = hidden_states + residual
hidden_states = RMSNorm(hidden_states)
```

传统实现需要执行两个独立 GPU Kernel：

    Residual Add Kernel

            ↓

    Intermediate Tensor

            ↓

    RMSNorm Kernel

存在问题：

-   Kernel Launch 调度开销
-   中间 Tensor 显存读写
-   额外 Global Memory Traffic

## 3. Fused Residual RMSNorm 优化方案

本版本使用 Triton 实现融合 Kernel。

优化前：

    Residual Add

    ↓

    RMSNorm

优化后：

    Fused Residual + RMSNorm Kernel

一次 Kernel Launch 完成：

1.  Residual Addition
2.  RMSNorm 计算
3.  输出写回

核心目标：

减少 Kernel 数量，同时减少中间 Tensor 存储。

## 4. Triton Kernel 设计

每个 Triton program 负责处理 hidden dimension 中的一行数据。

执行流程：

    Program ID

          |

    读取 hidden_states

          |

    读取 residual

          |

    计算 hidden_states + residual

          |

    FP32 RMSNorm

          |

    写入 output

数值策略：

-   支持 FP16 / BF16 / FP32
-   RMSNorm 内部采用 FP32 accumulation

## 7. 性能结果分析

实验结果：

相比 PyTorch Native：

-   最高约 3× speedup

相比 Unfused Triton：

-   中小规模 workload 下约 1.1～1.5× 加速

主要原因：

-   减少 Kernel Launch
-   减少 Global Memory Traffic
-   避免中间 Tensor 写回

性能限制：

在大 batch 或大 hidden dimension 场景下，融合收益可能降低。

原因：

-   Memory Bandwidth 限制
-   GPU Scheduling 开销
-   residual output 写回带来的额外 Memory Write
