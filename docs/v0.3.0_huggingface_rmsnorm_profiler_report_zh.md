# v0.3.0 Hugging Face RMSNorm 整模型 Profiler 归因报告

## 1. 实验配置

- Git commit：`4c63649`
- GPU：NVIDIA GeForce RTX 4090
- PyTorch：2.7.1+cu126
- CUDA：12.6
- Transformers：5.14.1
- 模型：随机初始化的紧凑 LlamaForCausalLM
- dtype：FP16
- batch size：1
- sequence length：32
- hidden size：512
- Transformer layers：4
- 替换 RMSNorm 数量：9

## 2. 正确性

替换后的模型通过输出一致性验证：

- 最大绝对误差：`0.000976562`
- 平均绝对误差：`0.000000272`
- 成功替换 RMSNorm：9 个

## 3. 端到端延迟

|实现|墙钟平均延迟|CUDA Event 平均延迟|
|---|---:|---:|
|Hugging Face 原始模型|1.009114 ms|1.010705 ms|
|Triton RMSNorm 模型|1.035308 ms|1.028106 ms|

对应速度比：

- 墙钟速度比：`0.974699×`，Triton 版本约慢 `2.60%`
- CUDA Event 速度比：`0.983074×`，Triton 版本约慢 `1.72%`

该单次 Profiler 结果与三轮正式 Benchmark 的“端到端基本持平”结论一致。
正式性能结论仍应以三轮 Benchmark 为准。

## 4. CUDA Kernel 归因

|指标|Hugging Face|Triton RMSNorm|变化|
|---|---:|---:|---:|
|整模型 CUDA Kernel 数/迭代|183|120|减少 63，约 `34.43%`|
|整模型 CUDA Kernel 累计时间/迭代|341.901 μs|247.220 μs|减少 94.681 μs，约 `27.69%`|
|RMSNorm Kernel 数/迭代|72|9|减少 63，约 `87.50%`|
|RMSNorm Kernel 时间/迭代|104.275 μs|9.767 μs|减少 94.508 μs，约 `90.63%`|
|RMSNorm CPU 标记时间/迭代|635.032 μs|409.852 μs|减少 225.180 μs，约 `35.46%`|

原始 Hugging Face RMSNorm 每次前向包含 9 个 RMSNorm，每个 RMSNorm
平均启动 8 个 CUDA Kernel；Triton 版本将每个 RMSNorm 融合为 1 个
`_rms_norm_forward_kernel`，因此每次前向只启动 9 个 RMSNorm Kernel。

## 5. 为什么 Kernel 明显减少，端到端仍未加速

Profiler 显示 Triton RMSNorm 确实减少了 Kernel 数量和 GPU 活跃时间，
但紧凑模型的墙钟延迟仍约为 1 ms。

近似计算：

- Hugging Face：墙钟 1009.114 μs，CUDA Kernel 累计 341.901 μs
- Triton：墙钟 1035.308 μs，CUDA Kernel 累计 247.220 μs

两者都有大量未计入 Kernel 活跃时间的主机调度、Kernel Launch 间隙、
框架执行和同步等待。Triton 版本虽然节省约 94.7 μs 的 Kernel 时间，
但这些收益在当前微型模型和短序列场景中被其他非 Kernel 开销及测量波动
抵消。

需要强调：CUDA Kernel 累计时间不是端到端关键路径时间，CPU 标记也可能
包含异步提交；因此不能把各项时间简单相加。若要精确定位空闲间隙，应使用
Nsight Systems 查看 CPU/GPU 时间线。

## 6. 可用于项目文档的结论

> 在紧凑 Llama FP16、batch=1、sequence=32 场景中，Triton RMSNorm
> 将每次前向的 RMSNorm CUDA Kernel 数从 72 个降至 9 个，减少 87.5%；
> RMSNorm Kernel 累计设备时间由 104.275 μs 降至 9.767 μs，减少约
> 90.6%。整模型 CUDA Kernel 总数减少约 34.4%，但端到端延迟仍基本持平，
> 表明在该微型模型中，算子融合收益受到主机调度、Kernel Launch 间隙及
> 其他模型算子开销的限制。

## 7. 限制

- 当前是随机初始化的紧凑模型，不是预训练大模型；
- 当前场景不是使用 KV Cache 的真实自回归 Decode；
- Profiler 只运行一个代表性配置；
- 单次 Profiler 延迟不用于替代三轮正式 Benchmark；
- 尚未使用 Nsight Systems 对 CPU/GPU 空闲间隙做时间线级分析。
