# v0.3.0 Hugging Face RMSNorm hidden_size=512 三轮对齐实验

## 1. 实验目的

本实验将模块级 RMSNorm 的 `hidden_size` 对齐到紧凑 Llama/Qwen2
整模型使用的 `hidden_size=512`，用于判断整模型端到端收益不明显是否
由小隐藏维度导致。

实验不下载预训练权重，直接测试 Hugging Face 原始 RMSNorm 与
LLM-KernelLab Triton RMSNorm 适配器。

## 2. 实验范围

- GPU：NVIDIA GeForce RTX 4090
- PyTorch：2.7.1+cu126
- CUDA：12.6
- Triton：3.3.1
- Transformers：5.14.1
- Git commit：`2d52b4a`
- 模型族：Llama、Qwen2
- dtype：FP16、BF16、FP32
- hidden size：512
- 场景：
  - batch=1，sequence=1
  - batch=1，sequence=32
  - batch=1，sequence=128
  - batch=4，sequence=32
- 正式运行：3 轮
- 原始记录：144 条
- 成对性能比较：72 组
- 所有记录状态：`ok`

## 3. 三轮总体结果

| dtype | Hugging Face 平均 P50/ms | Triton 平均 P50/ms | 平均加速比 | 中位数 | 范围 |
|---|---:|---:|---:|---:|---:|
| FP16 | 0.017804 | 0.003707 | 4.86× | 4.50× | 4.20～5.93× |
| BF16 | 0.017801 | 0.003904 | 4.59× | 4.50× | 4.13～5.96× |
| FP32 | 0.013522 | 0.003836 | 3.56× | 3.50× | 2.95～4.20× |

全部 dtype 和场景综合：

- Hugging Face 平均 P50：0.016376 ms
- Triton 平均 P50：0.003816 ms
- 三轮成对平均加速比：4.34×
- 中位加速比：4.50×
- 按两类平均延迟计算：4.29×
- 全部观测范围：2.95～5.96×

## 4. 模型族结果

|模型族|平均加速比|按平均延迟计算|
|---|---:|---:|
|Llama|4.39×|4.33×|
|Qwen2|4.28×|4.25×|

Llama 与 Qwen2 的结果接近，没有发现单一模型族的适配异常。

## 5. 正确性

三轮实验中 Triton 适配器最大绝对误差：

- FP16：0.003906250
- BF16：0.031250000
- FP32：0.000000954

所有场景均通过脚本中的 `torch.testing.assert_close`。

## 6. 结论

本次对齐实验确认：

1. `hidden_size=512` 下，Triton RMSNorm 本身仍有显著性能优势；
2. 整模型端到端收益不明显，不是因为小 hidden size 让 Triton Kernel 失效；
3. 前面的输入布局诊断已经确认 RMSNorm 输入和权重均为连续内存，
   因而也不是 `contiguous()` 产生实际数据复制；
4. 下一阶段需要用 GPU profiler 分析整模型中的 Kernel 调度、同步和
   其他算子占比，不能再仅凭单算子延迟推断端到端收益。

严谨表述：

> 在 RTX 4090 上，将模块形状对齐到紧凑 Llama/Qwen2 的
> hidden size=512 后，Triton RMSNorm 在三轮正式实验中仍获得
> FP16 约 4.86×、
> BF16 约 4.59×、
> FP32 约 3.56× 的平均加速。
> 因此，当前紧凑整模型端到端性能基本持平，不能归因于小 hidden size
> 或非连续内存复制。

## 7. 当前限制

- `single_token_no_cache` 是无 KV Cache 的单 Token 前向，
  不能称为真实自回归 Decode Benchmark；
- 当前整模型为随机初始化的紧凑模型；
- 尚未完成 Nsight Systems/PyTorch Profiler 级别的端到端归因；
- 尚未验证真实预训练权重和真实 KV Cache Decode。
